# top10-26-pusanuniv

Python 3.15.2와 macOS Apple Silicon에서 실행하도록 구성한 프로젝트입니다.

## 모델 평가 기반 TOP10

깃허브에는 코드·평가 기준·자동 검사와 최신 선정 결과 3개 파일을 올립니다.
원본 설문 응답·기업 자료·중간 데이터·실행 기록·가상환경·모델 가중치는 별도로 관리합니다.
저장소를 새로 내려받은 환경에서 원문 대조와 재계산을 수행하려면 제공 자료와 보존된 실행 기록을 별도로 배치해야 합니다.


최신 결과는 `data/demo/model_top10_2026-11-15/TOP10_선정결과.md`입니다.
같은 폴더의 `top10.json`은 화면 연결용이며 `기업별_모델평가.csv`에는 50개 기업의 점수를 담았습니다.
제공된 연봉과 모델의 워라밸·지역 인프라·직무 유망성·AI 안전성 평가를 기존 설문 가중치로 계산했습니다.
마크다운에는 10개 선정 근거, 항목별 원문 연결, 직군별 워라밸 집계, 계산식과 전체 50개 평가표를 기록했습니다.

워라밸은 제공된 주요 직군별 모델 평가를 동일 가중 평균합니다. 실제 인원 비중을 의미하지 않습니다.
지역 인프라는 제공 위치 표기만으로 평가하므로 같은 위치에는 같은 점수를 부여합니다.
직무 유망성과 AI 안전성은 산업·제품·직군·제공 AI 설명 및 안전하게 대응된 PDF 일부 직무 설명을 평가합니다.
비급여 입력에서는 기업명과 연봉을 제외했고, 공통 3점 대체나 정성 등급의 고정 점수 변환을 사용하지 않았습니다.
외부 기업 자료를 추가하거나 제공 연봉과 원본을 바꾸지 않았습니다. 모델 평가값은 실제 근로조건을 실측한 값과 구분합니다.

모델 원시 응답과 입력·실행 버전·해시는 `reports/model_evaluation_2026-11-15/`에 보존합니다.
저장된 응답으로 계산과 문서를 재생성하려면 다음 명령을 사용합니다. 새 모델 추론이나 다운로드는 필요하지 않습니다.

```bash
.venv/bin/python -B src/export_model_top10.py \
  --ratings-dir reports/model_evaluation_2026-11-15/attempt02 \
  --refinement-dir reports/model_evaluation_2026-11-15/refinement01 \
  --output-dir data/demo/model_top10_recheck \
  --audit-dir reports/model_top10_recheck/internal
```

연봉이 확인된 48개를 동일 비교집합으로 사용하고 부산·울산·경남 각 최소 1개를 포함하는
조합 중 가중 상대지수 합이 가장 큰 10개를 선정합니다. 연봉 미확인 2개도 4개 비급여 항목을
평가했으나 종합 계산에서는 보류합니다. 모델 가중치의 추가 학습은 수행하지 않았습니다.
기존 실측 근거 검증 경로의 상태를 임의로 바꾸지 않고 모델 평가 경로를 별도로 제공합니다.

`TOP10_시연용.csv`에서 확인합니다. 화면과 내보내기에는 ‘시연용 결과 · 검증 전’ 표시를 유지합니다.
시연 결과는 검증된 실제 기업 순위와 구분하며, 기존 실제 평가 경로의 보류 상태는 유지합니다.
기존 모델의 원문 판독과 제공된 50개 명단을 재검사해 사용하고, 시연 실행 설정·계산 추적은 내부 기록으로 분리합니다.

```bash
.venv/bin/python -B src/run_mvp_selection.py \
  --scenario-config reports/mvp_demo_2026-11-15/internal/scenario.json \
  --output-dir data/demo/mvp_top10_recheck \
  --audit-dir reports/mvp_demo_recheck/internal
```

공개 결과와 내부 기록은 서로 다른 경로를 지정해야 하며 기존 결과는 덮어쓰지 않습니다.
화면 연결에는 공개 결과 JSON만 사용합니다. 커밋과 푸시는 사용자가 진행합니다.

## 기존 5개 항목 최종 선정 계산기

`src/relative_selection.py`에 공통 비교집합 정규화·문서 기준 상대지수·지역 조건을 구현했습니다.
부산·울산·경남 각각 최소 1개를 포함하는 10개 조합 중 상대지수 합이 가장 큰 조합을 찾습니다.
여러 최적 조합이 동점이면 임의로 확정하지 않고 공통 포함 기업과 공동 후보를 표시합니다.
원점수가 없는 항목은 미상으로 유지하며 기존 5개 기준과 설문 가중치를 유지합니다.
가상 입력 파일이 없는 환경에서는 첫 명령으로 생성하고, 이미 있으면 생성은 생략합니다.

```bash
.venv/bin/python -B src/selection_function_cases.py \
  --output data/testing/selection_function_input.json
.venv/bin/python -B src/run_relative_selection.py \
  --synthetic-input data/testing/selection_function_input.json \
  --output-dir data/selection/synthetic_recheck
.venv/bin/python -B src/run_relative_selection.py \
  --output-dir data/selection/real_recheck
```

가상 자료는 기능 검사 전용이며 실제 기업 근거에 추가하지 않습니다.
실제 실행은 기존 원문·직무·구절 근거를 재검사한 평가표로 입력을 만들고 자동 검증 상태를 확인합니다.
외부 JSON을 실제 점수라고 표시해 입력하는 경로는 허용하지 않습니다. 같은 출력 경로는 덮어쓰지 않습니다.
실측 근거만을 허용하는 기존 경로에서는 비급여 점수와 공통 직무·범위가 미확정이므로 선정을 보류합니다.
제공 자료를 해석한 모델 평가에 따른 10개는 위의 최신 결과에서 확인합니다.
상세 규칙은 `선정계산기_안내.md`, 실행 기록은 `reports/selection_calculator_2026-11-15/검증안내.md`를 참조합니다.

## 실제 기업 정보는 제공 자료만 사용

기업 후보·평가 근거·가중치는 사용자가 제공한 기업 목록, 설문, 기준 문서만 사용합니다.
문서에 적힌 주소를 열어 외부 기업 정보를 추가하지 않습니다. 문서 원본과 처리 자료의
해시 및 기업·기재 위치·직무·원문 필드를 검사하고, 외부에서 수집한 자료는 실제 평가 입력에서 거부합니다.
가상 문장은 기능 검사에만 사용하며 실제 기업의 근거나 평가 정확도 수치로 바꾸지 않습니다.

원본 150개는 모집단 대조용이며 연구팀이 선별한 새 50개 명단이 실제 평가 대상입니다.
최종 10개는 이 50개 안에서 선정합니다. 새 명단의 순번과 원본 150개 순번은 별개입니다.
기업명·지역이 정확히 일치하거나 지역 괄호 표기만 다른 경우에만 이전 자료를 연결합니다.
대응이 미확정인 기업도 50개 명단에 그대로 유지하고 불확실한 다른 기업 자료를 합치지 않습니다.

연봉은 새 엑셀을 우선하고 PDF 값을 별도 참고 열에 병기합니다.
새 엑셀에서 미확인인 연봉은 PDF 값으로 채우지 않습니다. 기존 모형 기준연봉 7,150만원은 유지합니다.

제공된 선별 엑셀의 원문 셀로 실제 입력을 만들려면 다음 명령을 사용합니다.

```bash
.venv/bin/python -B src/prepare_user_evidence.py
```

기본 출력은 `data/evidence/selected50/`이며 새 명단에 연결된 50개 입력을 생성합니다.
기재 위치를 실제 사업장 확인으로 해석하지 않으며, AI 설명은 제공 자료의 작성자 정성 판단으로 보존합니다.
점수와 순위는 이 명령에서 생성하지 않습니다. `--company-id selected50:001`로 한 기업만 만들 수도 있습니다.
이미 있는 출력 폴더는 덮어쓰지 않습니다. 원본이 갱신되면 새로 제공받은 파일의 해시와 출처 정책을 함께 갱신해야 합니다.

과거 `data/evidence/ai_resilience_2026-11-14/`의 외부 직무소개 입력은 과거 실험 기록입니다.
현재 출처 정책에서는 실제 평가에 사용할 수 없습니다. 이전 보고서는 이력 확인을 위해 보존합니다.

## 선별 50개 평가표와 학습·평가 기준

최신 반영 결과는 `data/evaluation/selected50_2026-11-15/`의 JSON·CSV와
`reports/company_evaluation_2026-11-15/작업안내.md`를 참조합니다.
확인용 엑셀에는 50개 평가표·250행 평가 근거·자료 대조·기준과 가중치를 담았습니다.
연봉 48개와 정성 참고를 연결했으며 비급여 점수와 종합 순위는 근거 없이 채우지 않았습니다.

재생성할 때에는 기존 결과를 보존하도록 새로운 출력 경로를 지정합니다.

```bash
.venv/bin/python -B src/prepare_selected50.py --output data/processed/selected50_recheck.json
.venv/bin/python -B src/build_company_evaluation.py --output-dir data/evaluation/selected50_recheck
.venv/bin/python -B src/build_learning_standard.py --output-dir data/learning/provided50_recheck
```

`configs/provided_data_learning.json`은 제공 자료만 사용하는 지침과 항목별 판단 규칙입니다.
`configs/ai_evaluation.yaml`의 비급여 1~5점 기준과 `configs/document_model.yaml`의 상대지수 모형을
함께 기록합니다. `data/learning/provided50_2026-11-15/`에는 직군 참고 예시 8개, 사실 확인 사례 50개,
정답을 제외한 모델 입력 50개와 평가 기준이 있습니다. 모델 가중치를 학습하거나 실제 평가를 완료한 결과가 아닙니다.
사실 확인 정답은 검증 전용이며 모델 입력에 포함하지 않습니다. 같은 사례를 학습에 쓰면 독립 검증 성적으로 표시하지 않습니다.

직군·AI 등급과 설명은 일반 정성 참고로 보존하고, 로봇·물리 자동화와 생성형 AI를 구분합니다.
실측 근거 경로에서 워라밸·인프라·직무 유망성의 근거가 없는 부분은 확정 사실로 채우지 않습니다.
사용자가 허용한 모델 평가 경로에서는 제공 산업·위치·직군을 공통 기준으로 해석하되 기업명은 입력하지 않습니다.
자료 부족을 3점으로 바꾸거나 제공 등급을 확정 점수·확률로 자동 변환하지 않습니다.
기존 7항목 0~100점 경로는 별도 이력이며 새 5항목 상대지수 표에 혼합하지 않습니다.
최종 10개 확정 전에는 모델 응답의 근거 적합성·공통 비교범위·가중치와 지역 최소 조건을 검증해야 합니다.

## 선별 50개 로컬 모델 사실 읽기 검사

`src/read_selected50.py`는 원본·처리 자료의 해시를 확인한 뒤 선택된 로컬 모델로
선별 50개를 한 번씩 읽습니다. 모델에는 원문 셀 값과 출력 필드·지침만 전달하며 검증 정답은 보내지 않습니다.
미확인 연봉은 미상으로 유지하고 정성 설명은 원문 그대로 읽어야 통과합니다.
없는 점수를 만들거나 값을 바꾸거나 응답이 잘리면 해당 응답을 차단합니다. 자동 재시도는 하지 않습니다.

```bash
.venv-models/bin/python -B src/read_selected50.py \
  --hf-home "/모델/캐시/경로" \
  --output-dir reports/selected50_reading_recheck
```

맥용 모델 의존성이 설치된 파이썬을 사용합니다. 기존 기록을 덮어쓰지 않도록 새로운 출력 경로를 지정합니다.
검사 중에도 기업별 원시 응답·오류와 `summary.json`을 남깁니다. 중단된 실행은 완료로 표시하지 않습니다.
제공 자료나 설정이 실행 중 바뀌면 결과 사용을 차단합니다. 모델은 이미 저장된 고정 버전만 읽습니다.
이 검사는 사실 복사와 미상 유지·점수 생성 금지 지시 준수를 확인하며,
기업 점수의 타당성이나 최종 10개 선정의 정확도를 검증한 결과가 아닙니다.
이번 실행 기록은 `reports/selected50_reading_2026-11-15/검증결과.md`와
같은 보고서의 `attempt01/`에서 확인할 수 있습니다.

## 업무 근거 분류와 기존 5개 항목 평가 연결

사용자 결정에 따라 **기존 5개 항목과 설문 가중치만 유지**합니다.
급여·AI 등급 2개 항목만 사용하는 참고 시나리오는 만들지 않습니다.
모델이 원문을 읽거나 구절을 분류하는 데 성공했다는 사실을 기업 점수 검증으로 바꾸지 않습니다.

`src/classify_selected_evidence.py`는 기업 설명을 구절별로 분리해 원문 셀·문자 위치·해시와 연결합니다.
가상 기능 검사를 모두 통과한 뒤 물리 자동화·디지털 자동화·혼합 자동화·업무 서술·정성 설명을 분류합니다.
자동화 표지가 없는 문장에서는 자동화 분류를 출력 후보에서 제외합니다.
생성형 AI가 명시됐는지는 별도 기록하며 디지털 자동화를 모두 생성형 AI로 해석하지 않습니다.
직군 일반 기준은 개별 기업의 실증 근거로 합치지 않습니다.

```bash
.venv-models/bin/python -B src/classify_selected_evidence.py \
  --hf-home "/모델/캐시/경로" \
  --output-dir reports/evidence_classification_recheck
.venv-models/bin/python -B src/classify_pdf_job_references.py \
  --classification-dir reports/evidence_classification_recheck \
  --hf-home "/모델/캐시/경로" \
  --output-dir reports/pdf_job_reference_recheck
.venv/bin/python -B src/attach_evidence_assessment.py \
  --classification-dir reports/evidence_classification_recheck \
  --pdf-reference-dir reports/pdf_job_reference_recheck \
  --output-dir data/evaluation/assessed50_recheck
```

두 번째 명령은 안전하게 대응된 26개 PDF의 일부 직무 설명을 별도 참고로 분류합니다.
세 번째 명령은 모델을 다시 실행하지 않고 원문·응답·가중치를 재검사해 평가표와 구절 분류 CSV를 만듭니다.
PDF의 특정 직무 설명을 새 명단의 여러 채용 직군이나 회사 전체 점수로 합치지 않습니다.
등급 표현을 실제 업무로 읽었거나 자동화 표지와 분류가 엇갈린 구절은 추가 점검에서 보류합니다.

비급여 점수가 없는 항목은 미상으로 유지하며 종합지수·선정 명단을 만들어내지 않습니다.

## 근거 추출 첫 단계

`src/extract_ai_evidence.py`는 인공지능 대체 안전성 한 항목의 관련 문장만 선택합니다.

프로그램은 앞의 세 분류를 근거로 선택하고 원문 위치와 해시를 확인해 인용문·출처·수집일을 연결합니다.

입력은 기존 평가기와 같은 기업·사업장·직무 및 출처 묶음이며, 각 출처에는 추가로
`scope` 객체가 필요합니다. 이 객체에 `company_id`, `company_name`, `workplace`,
`target_job`을 명시합니다. 대상과 다르거나 범위가 빠진 출처는 선택 대상에서
제외하고 이유를 기록합니다. 범위 메타데이터의 일치가 원문 사실성 검증을 뜻하지는 않습니다.

모델은 한 번만 읽고 네 사례 안의 문장 열두 개를 순차 분류합니다. 자료 없음과 다른 직무 두 사례는
프로그램이 모델 호출 없이 처리합니다. 기대 문장 목록은 모델 입력에 포함하지 않습니다.

허용 목록과 정확히 일치해야 하며 점수·설명·새 인용문 등 추가 필드는 차단합니다.
선택한 문장 식별자의 유효성·중복도 확인합니다. 관련 없는 문장을 고를 수 있으므로 출처 연결 검사와 의미상
관련성 검증은 구분합니다. 충돌 시험은 두 서술을 보존하는지 확인하는 것이며
자동 충돌 판정이나 해소가 구현된 것은 아닙니다. 기존 네 항목 평가기는 별도로 보존합니다.

2026-11-14 최종 가상 시험은 여섯 사례가 모두 기대 결과와 일치했습니다. 이 중 네 사례의
열두 문장은 실제 모델이 분류했고, 두 사례는 프로그램에서 처리했습니다. 이 자료는 반복
개발에 사용한 작은 시험 집합이므로 실제 기업 자료에 대한 독립 검증을 대신하지 않습니다.

## 업무 유형과 비중을 나눈 시험 평가

`src/assess_ai_resilience.py`는 원문 연결을 다시 확인한 뒤 점수 대신 업무 유형을 모델에 묻습니다.
모델은 각 근거 문장을 반복 사무·현장 작업·사람 판단·혼합 업무·정보 부족·근거 충돌로 분류합니다.
원문에 비중 표현이 있을 때만 별도로 그 표현이 실제 업무에 적용되는지 확인합니다.
원문에 없는 비중은 응답 선택지에서 제외하며, 원문의 표현과 문자 위치를 함께 기록합니다.
비중 근거의 위치는 해당 근거 문장 안의 위치입니다.

프로그램은 `configs/ai_evaluation.yaml`의 기존 다섯 점수 기준에 맞춰 다음처럼 연결합니다.
명시된 주된 업무를 우선하고, 주된 업무 유형이 서로 충돌하면 평균을 내지 않고 보류합니다.

| 확인한 업무 유형 | 확인한 비중 | 시험 점수 |
|---|---|---|
| 반복 사무 | 대부분·전부 등 | 한 점 |
| 반복 사무 | 주로·상당 부분 | 두 점 |
| 반복 사무와 현장 수행·사람 판단이 모두 명시됨 | 주된 유형은 미특정 | 세 점 |
| 현장 수행·사람 판단 | 주로 | 네 점 |
| 현장 수행·사람 판단 | 대부분·전부 등 | 다섯 점 |
| 단일 업무 유형만 확인됨 | 비중 미상 | 판단 보류 |

혼합 업무에 적힌 비중이 어느 유형을 가리키는지 연결되지 않으면 점수를 보류합니다.
서로 다른 출처가 있으면 별도로 모순·양립·보류를 모델에 묻습니다.
단일 출처 내부의 모순은 별도 충돌 검사 없이 문장 유형 판단에서 보류할 수 있습니다.
업무 유형과 비중의 의미상 판단은 여전히 모델에 의존합니다. 원문 연결 검사는 사실성을 보증하지 않습니다.

```bash
.venv/bin/python -B src/test_ai_resilience_local.py \
  --device mps --hf-home "/기존/모델/캐시/경로" \
  --real-bundle "/실제/기업자료.json"
```

검토 후 분류 방식을 비교하려면 같은 명령에 `--reasoning`을 추가합니다.
이 방식은 모델을 새로 내려받거나 학습하지 않고 기존 모델의 추론 방식을 바꿉니다.
내부 검토가 제한 안에 끝나지 않으면 답을 추측하지 않고 응답 오류로 처리합니다.
검토 내용은 출력하거나 기록하지 않으며 최종 분류와 사용량만 남깁니다.

기존 실패 사례 일곱 개의 입력·기대값은 유지합니다. 여기에 비중 구분과 비중 부족 사례
직원 수 비율의 오용 방지를 포함한 네 개를 더한 개발 사례 열한 개를 먼저 실행합니다. 전부 통과할 때만 별도 고정한 추가 확인
사례 여덟 개를 실행합니다. 기대 답안은 모델에게 전달하지 않습니다. 원문·결과·유형·비중·모델 호출과
구현 해시를 새 보고서 폴더에 남기며 기존 결과는 덮어쓰지 않습니다.

실제 기업의 점수 추론은 같은 실행에서 개발·확인 사례를 모두 통과했을 때만 수행합니다.
실패 또는 미실행 사례가 있으면 실제 점수 추론을 건너뛰고 `model_validation_failed`와 결측 점수를 반환합니다.
독립 실행 평가기는 실제 자료에 대한 자동 모델 검증 확인이 없으면 `model_validation_required`로 보류합니다.
이는 사람의 승인 절차가 아닌 자동 검증 조건입니다. 이 작은 가상 사례 집합을 통과해도 실제 기업
전체의 정확성을 보증하지 않습니다.

`proposed_score`는 실측 대체 확률이 아닌 모형상 시험 평가입니다.
사업장과 직무 범위의 사실성, 다른 평가 항목, 공통 비교 집합을 아직 확인해야 하므로
`ready_for_ranking`은 거짓으로 유지합니다. 사업장 미특정 전사 직무소개를 기업 전체나
특정 사업장의 점수로 일반화하지 않습니다. 기존 네 항목 평가기는 별도로 보존합니다.

## 전달받은 기업·설문·PDF 연결

세 자료를 한 번에 읽고, 기업 순번·이름·지역과 문서의 연봉 수치를 검산합니다.
기업 CSV는 UTF-8과 CP949를 지원합니다. 설문 가중치는 실제 응답에서 중요·비중요
선택 횟수를 다시 집계해 문서 모형의 `1 + 0.1×중요비율 - 0.1×비중요비율`로 계산합니다.
기존 `calculate_survey_weights.py`의 7개 기준 min-max 방식과는 별도입니다.

```bash
python src/prepare_project_data.py \
  --companies "/경로/buulgyeong_midsized_companies_total.csv" \
  --survey "/경로/지역기업 TOP10선발 설문조사(응답) (1).csv" \
  --pdf "/경로/직업만족도_AI분석_자료와프롬프트.pdf"
```

원본 바이트는 `data/raw/company_catalog.csv`, `survey_responses.csv`,
`직업만족도_AI분석_자료와프롬프트.pdf`로 보존하고 SHA-256과 원래 파일명을 기록합니다.
설문 개인별 응답을 생성 JSON에 다시 노출하지 않으며 원본·처리 데이터는 기존
`.gitignore`의 `data/` 규칙을 따릅니다. 다른 컴퓨터에서는 세 원본을 별도로 전달받아
같은 명령으로 처리합니다.

`data/processed/`에 생성되는 결과:

- `company_catalog.json`: 원본 150행과 PDF 연봉 보유 135행의 연결 결과.
- `document_companies.json`: 중복 1행을 표시한 문서 자료와 134개 단위 연봉 검산.
- `document_survey_weights.json`: 실제 설문 집계, 활성 5개 가중치와 정규화 비중.
- `document_analysis_inputs.json`: 문서 기준 5개 항목의 근거 확보 현황. 이전 50개 기업 요약기 입력과 별도입니다.
- `data_readiness.json`: 계산 가능 범위, 추가 자료, 지역별 최소 선정 조건.
- `source_manifest.json`: 세 입력 파일의 원본 이름·해시·바이트 수.

이미 결과 파일이 있으면 덮어쓰지 않습니다. 다시 처리할 때는
`--output-dir data/processed/새이름`을 지정합니다. 원본이 바뀌었다면
`--raw-dir data/raw/새이름`도 함께 지정합니다. `--companies`, `--survey`, `--pdf`를
생략하면 `data/raw/`의 위 표준 파일명을 사용합니다.

이번 경로는 이전 `companies_clean.csv`, `company_analysis_inputs.json`, 7개 기준
사람 검토 양식·계산기를 생성하거나 변경하지 않습니다. `document:001` 형태의 ID는
문서 원본 순번이며, 이전 50개 기업의 숫자 ID와 자동으로 연결하지 않습니다.

현재 자료에서는 연봉지수와 설문 가중치를 계산할 수 있습니다. 워라밸·인프라·직무
유망성·AI 안전성의 동일 직무·사업장 범위 원점수와 선정 자격은 추가 검토가 필요해
종합순위와 최종 TOP10은 생성하지 않습니다. PDF의 정성 AI 등급은 확정 점수나
확률로 자동 변환하지 않습니다. 경력 확보와 수평적 조직문화는 문서 모형에서 보류합니다.

## 로컬 LLM

```bash
python src/test_local_llm.py --device auto
python src/analyze_company_local.py --company-id 1 --device auto
python src/evaluate_company_local.py --input <입력.json> --output <새_결과.json> --device auto
```

`auto`는 CUDA → Apple MPS → CPU 순서로 사용 가능한 장치를 선택합니다.
CPU로 실행하려면 `--device cpu`, Apple GPU를 지정하려면 `--device mps`를 사용합니다.
MPS를 지정했는데 사용할 수 없는 환경이면 실행 가능한 장치를 안내하는 오류가 표시됩니다.

모델은 `Qwen/Qwen3-1.7B`입니다. 첫 실행에는 Hugging Face에서 모델을 내려받으므로
인터넷 연결과 수 GB의 여유 공간이 필요합니다. 모델 가중치는 설치 과정에서 내려받지 않았습니다.
Mac에서는 bitsandbytes 4비트 양자화 대신 MPS의 FP16을 사용하며, CPU에서는 FP32를 사용합니다.
기존 4비트 CUDA 실행보다 메모리를 더 사용할 수 있습니다.

결과 JSON에는 실행 `device`를 기록합니다. 최대 GPU 메모리는 CUDA에서만 측정하므로
MPS와 CPU의 기존 `peak_allocated*` 값은 `null`입니다. MPS의 현재 할당량은
`current_allocated*`에 별도로 기록합니다. CPU의 GPU 메모리 값은 `null`입니다.

평가기의 `prompt_version`은 `evaluation_v2_no_prefilled_answer`입니다.
자료 부족 상태로 채운 입력 검사용 객체는 모델에 전달하지 않고, 항목별 출력 형식과
제약만 전달합니다. 구조·출처 검사가 통과해도 근거의 의미상 적합성이 검증된 것은
아니며, 종합순위 연결 전까지 `ready_for_ranking`은 거짓으로 유지합니다.

기존 모델 캐시를 재사용하려면 실행 전에 `HF_HOME`을 해당 캐시의 상위 폴더로
설정합니다. 이 경로가 다르면 같은 모델을 다시 내려받을 수 있습니다.

## 검증 범위

패키지 간 의존성 검사, 기존 테스트, 장치 선택 테스트와 작은 Qwen3 모델의
로컬 저장·재로딩·CPU 추론을 검사합니다. 작은 모델 시험에는 네트워크나 실제 기업 자료를 사용하지 않습니다.
2026-11-14의 8GB Mac 실제 시험에서는 Qwen3-1.7B의 Apple GPU 로딩과 기본 정보
추출이 성공했습니다. 그러나 비급여 평가 대조 시험에서는 근거 누락·부정확한 인용
등이 발생하여 자동 검사가 점수를 차단했습니다. 모델 실행 성공과 평가 정확성을
구분하며, 현재 평가 결과를 실제 기업 종합순위에 사용하지 않습니다.

자료 가져오기·기본 답안 미전달·새 근거 추출 검사를 포함한 자동 테스트는 56개입니다.
가중치·연봉 자료 연결은 실제 원본으로 검산했지만, 비급여 평가의 의미상 정확성은
이 테스트 수에 포함된 보증이 아닙니다.

## 기업 평가 대시보드

`dashboard/index.html`을 브라우저로 열면 선정 결과와 전체 50개 기업 평가를 확인할 수 있습니다.
검색·지역 및 선정 여부 필터·정렬·최대 3개 기업 비교·원문 근거와 가중 기여도 상세·결과 다운로드·인쇄를 제공합니다.
화면의 비급여 점수는 제공 자료를 해석한 모델 평가값이며, 종합지수는 100점 상한의 점수가 아닙니다.
추가 패키지나 API 서버 없이 저장된 결과를 사용합니다.

평가 결과가 바뀌면 다음 명령으로 연결 데이터를 다시 생성합니다.

```bash
.venv/bin/python -B src/build_dashboard.py
```

로컬 서버로 열려면 다음 명령을 실행한 뒤 `http://127.0.0.1:8765`에 접속합니다.

```bash
.venv/bin/python -B -m http.server 8765 --bind 127.0.0.1 --directory dashboard
```

생성기는 선정 JSON·전체 CSV·모델 평가·계산 기록을 대조하고 50개 기업과 48개 공통 비교집합의 연결 및 기여도 합을 확인합니다. 원본 자료와 평가 결과는 변경하지 않습니다.
